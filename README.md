# GitVela

GitVela is a Windows desktop client for local Git repositories. Browse history, compare files, stage or unstage whole files, and commit staged changes. The branch panel supports creating, switching, renaming, and safely deleting local branches, plus browsing tags. For a merge commit, select the parent to compare against. Selecting a commit opens the diff for the previously selected path when available, or the first changed file.

Select **Worktrees** in the repository sidebar to list and open linked checkouts. **New…** creates a checkout at an unused absolute path, using an available local branch or a new branch from the selected commit. To remove a linked checkout, open a different worktree and confirm removal in the panel. GitVela keeps the branch and requires an unlocked checkout on a branch with no modified, untracked, or ignored files. The list checks for external changes every five seconds while the panel is open.

Switch the repository sidebar between **Files**, **Changes**, **Branches**, and **Worktrees**. The right-hand preview sits above Git Log and Changed Files. Use **History** in the preview header to collapse or reopen both history panels.

Open a file from **Files**, or choose **Edit file** in the working-file preview. The editor supports undo and redo, Find / Replace, and Ctrl+S. Saving updates the working copy and checks for changes made by other tools before replacing the file. It preserves UTF-8 BOM and consistent LF or CRLF line endings. The editor accepts UTF-8 regular files up to 512 KiB and 12,000 line breaks.

Use **Search…** in Git Log to search the full history by message, author, branch, or commit date, or look up a commit by hash. Results are paginated and open in the same Changed Files and Diff panels. Right-click a commit or press **Shift+F10** on its row to copy its hash or message, or start a branch from it. Switch Changed Files between Flat and Tree, or double-click a file to maximize the diff. Use **Settings** for theme, file layout, and resetting panel sizes.

Git metadata and changes in the worktree root trigger a debounced refresh. A five-second check covers edits in nested working directories and filesystems without reliable notifications.

The **Git** menu contains Commit, Fetch, Pull, Push, Stash, Worktrees, and repository setup. Click or right-click a branch to see its available actions, including showing its commit in Git Log, creating a branch from its tip, or checking out a local branch.

Use **Amend…** in Working Changes to edit the current commit message and include staged changes. Review the HEAD warning before confirming. **Stash…** saves tracked changes, optionally includes untracked files, and offers Apply, Pop, and confirmed Drop. Apply and Pop start from a clean working tree and can restore staged changes. Pop keeps the stash when applying fails.

Use **Git → Fetch…**, **Pull…**, and **Push…** to synchronize with a remote. Pull requires a clean working tree and protects ignored files from being overwritten. A branch without an upstream can publish under its current name and set its upstream on success. Authentication uses your configured Git credential helper and SSH setup. If Git needs terminal interaction, complete it in a terminal and retry.

To publish a new project, select **Git → Initialize Project…** and choose its existing folder. Review the Working Changes, stage the files and create the first commit, then select **Git → Publish to GitHub…**. Check the signed-in account, review the name and visibility, and choose **Create and push**. Visibility defaults to private. The flow creates the repository under your personal GitHub account, adds `origin`, and pushes the current branch. **Git → Manage Remotes…** lets you add, edit, or remove remote configuration, including when you already created the repository elsewhere.

See [GitVela.md](GitVela.md) for the architecture and roadmap.

## Windows development

Run from the project root in a PowerShell session with Go, Git and fnm available. Wails and its JavaScript runtime are pinned to 3.1.0. Node.js 24 is selected per session.

```powershell
fnm env --shell powershell | Out-String | Invoke-Expression
fnm install 24
fnm use 24
$env:GOTOOLCHAIN = 'go1.27.3'
$env:GOBIN = Join-Path $PWD '.tools/bin'
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0
$gitRoot = Split-Path (Split-Path (Get-Command git).Source)
$env:Path = "$env:GOBIN;$gitRoot/usr/bin;$env:Path"
wails3 doctor
wails3 dev
```

Stop the dev process before running a production build. Both modes write to the same output directory.

```powershell
wails3 build
go test ./...
go vet ./...
npm --prefix frontend run typecheck
npm --prefix frontend test
```

The production executable is at `bin/gitvela.exe`. Bindings are generated by the Wails build.

## Desktop smoke test

Start `wails3 dev -tags desktop_smoke` to enable WebView2 debugging on port 9331 using an isolated profile under `.tools`. In a second PowerShell session with fnm initialized and Node 24 selected, run `node tests/desktop-smoke.mjs` from the project root. The smoke test opens this repository and checks the initial commit's real Git diff through the desktop UI. To exercise Worktree creation, switching, and removal, pass a disposable clone on branch main as the first argument and set GITVELA_SMOKE_WORKTREE to an unused absolute directory path. The smoke test creates a branch in the clone. Set `GITVELA_SMOKE_MVP=1` to also check history search, commit actions, settings, and diff maximization. To test Amend, Stash, Fetch, Pull, and Push, use a disposable clone and set `GITVELA_SMOKE_M2_REMOTE` to an unused absolute path for a local bare test repository. Set `GITVELA_SMOKE_PROJECT=1` to test initialization, first commit, remote management, and the publication form. Optionally set `GITVELA_SMOKE_GITHUB_LOGIN` to verify the signed-in account and review screen against GitHub without creating a repository. Set `GITVELA_SMOKE_EDITOR=1` with a disposable clone to verify editing, undo, save, staging, and protection against external edits.

```powershell
go test ./internal/git -run '^$' -bench BenchmarkReadHistoryAndDiff -benchmem -benchtime 5x
```

The benchmark creates a temporary 10,000-commit repository. It measures Go and Git CLI time, excluding WebView rendering.
